# Batch Resolver Example

This sample demonstrates how to use **batch resolvers** in ArianeGraphQL to solve the N+1 query problem.

## What is the N+1 Problem?

When you query a list of items and each item has a related object, naive implementations make 1 query for the list + N queries for each related item.

**Example:** Fetching 10 posts with their authors
- 1 query to fetch all posts
- 10 queries to fetch each author (one per post)
- **Total: 11 database queries** 😱

## How Batch Resolvers Solve This

Batch resolvers collect all related IDs during query execution and fetch them in a single batched query.

**With batch resolvers:**
- 1 query to fetch all posts
- 1 batched query to fetch all authors at once
- **Total: 2 database queries** 🎉

## Running the Example

1. Start the server:
   ```bash
   ../gradlew :sample:run
   ```

2. Open GraphQL Playground at http://localhost:3000/graphql

3. Run this query:
   ```graphql
   query {
     posts {
       id
       title
       author {
         id
         name
         email
       }
     }
   }
   ```

4. Watch the console output to see the batching in action!

## Console Output Explained

### Without Batch Resolvers (N+1 Problem)
```
[QUERY] Fetching all posts...
[DB] PostRepository.findAll()
[DB] UserRepository.findById(1)
[DB] UserRepository.findById(2)
[DB] UserRepository.findById(1)
[DB] UserRepository.findById(3)
[DB] UserRepository.findById(2)
[DB] UserRepository.findById(4)
[DB] UserRepository.findById(1)
[DB] UserRepository.findById(5)
```
**8 posts = 9 database queries** (1 for posts + 8 for authors)

### With Batch Resolvers ✨
```
[QUERY] Fetching all posts...
[DB] PostRepository.findAll()

[BATCH RESOLVER] Fetching 5 users in a single batch:
[BATCH RESOLVER] User IDs: 1, 2, 3, 4, 5
[DB] UserRepository.findAllByIds(1, 2, 3, 4, 5)
[DB] ^ Single query fetching 5 users!
[BATCH RESOLVER] Successfully fetched 5 users
```
**8 posts = 2 database queries** (1 for posts + 1 batched for all unique authors)

Notice how the framework automatically:
- Collected the author IDs of all 8 posts: `1, 2, 1, 3, 2, 4, 1, 5`
- Deduplicated them before calling the loader: `1, 2, 3, 4, 5`
- Fetched them in a single query
- Distributed the results back to every post (users 1 and 2 appear on several posts but are only fetched once)

## Code Walkthrough

### 1. Define Your Data Models

```kotlin
// sample/src/main/kotlin/com/arianegraphql/sample/data/SampleData.kt

data class User(
    val id: String,
    val name: String,
    val email: String
)

data class Post(
    val id: String,
    val title: String,
    val content: String,
    val authorId: String  // Foreign key to User
)
```

### 2. Declare the Batch Resolver on the Field

That's the only step — the DataLoader is created and registered automatically for every request:

```kotlin
// sample/src/main/kotlin/com/arianegraphql/sample/server.kt

resolvers {
    Post {
        author.batch(
            key = { _, post -> post.authorId!! }
        ) { keys ->
            // One database call for all keys; missing keys resolve to null
            UserRepository.findAllByIds(keys.toList())
                .filterNotNull()
                .associate { it.id to User(it.id, it.name, it.email) }
        }
    }
}
```

`author` is a typed field reference generated by the codegen plugin; it registers plain
resolvers with the invoke syntax (`author { args -> ... }`) and batch resolvers with
`.batch`. Without generated code, the same declaration uses the core DSL:

```kotlin
type<Post>("Post") {
    resolveBatch<Unit, String, User?>(
        field = "author",
        keyExtractor = { _, post -> post.authorId }
    ) { keys ->
        UserRepository.findAllByIds(keys.toList())
            .filterNotNull()
            .associate { it.id to User(it.id, it.name, it.email) }
    }
}
```

## Key Concepts

### Mapped Semantics
The loader receives the deduplicated `Set` of keys and returns a `Map` of key to result.
Keys missing from the map resolve to `null` — no placeholder objects needed.

### Per-Request DataLoaders
A fresh DataLoader is created for each request, so results are never cached across
different users or requests. The loader is named `Post.author`, which makes it traceable
in graphql-java's per-loader statistics.

### Loader Environment
Inside the loader you have access to the request context and the source/arguments of
each key:

```kotlin
author.batch(key = { _, post -> post.authorId!! }) { keys ->
    context          // the request's GraphQLContext
    itemFor(key)     // the source post and arguments behind one key
    ...
}
```

### Type Safety
The batch resolver is fully type-safe:
- `S` = Source type (Post)
- `A` = Arguments type (Unit for fields without arguments)
- `K` = Key type (String - the user ID)
- `R` = Result type (User?)

## Try These Queries

### Query a Single Post
```graphql
query {
  post(id: "101") {
    title
    author {
      name
    }
  }
}
```

### Query Multiple Posts
```graphql
query {
  posts {
    title
    author {
      name
      email
    }
  }
}
```

### Without Author Field (No Batching Needed)
```graphql
query {
  posts {
    id
    title
    content
  }
}
```

## Performance Comparison

| Scenario | Without Batching | With Batching |
|----------|------------------|---------------|
| 10 posts | 11 queries | 2 queries |
| 100 posts | 101 queries | 2 queries |
| 1000 posts | 1001 queries | 2 queries |

The performance improvement is **dramatic** for large result sets!
